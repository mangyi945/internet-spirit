## 房间码：一个人创建，另一个人输入

![房间码](E:\工\screens\11-roomcode.png)

1. A 点 **创建房间码** → 出现 4 位数字，比如 `5818`
2. B 输入 `5818` → 点 **加入**
3. 自动完成握手，直接开始传

**没有二维码，没有应答码，不用摄像头。**

### 为什么以前非要两步

WebRTC 的连接需要**双方各出一半信息**：A 的网络位置和证书指纹、B 的网络位置和证书指纹。所以「A 发一份，B 回一份」是协议层面的硬要求，不是偷懒。

要做到「一个人生成、一个人输入」，中间必须有个东西把这两半撮合起来——就是那个 4 位数字背后的**会合点**。

### 会合点是什么

就是 `启动.bat` 那个窗口。它只做一件事：

```
A 把「我的位置」放进去  ──┐
                          ├─→ 房间码 5818
B 凭 5818 取出来        ──┘
```

- **不存消息、不存账号、没日志**
- 房间 10 分钟自动过期
- 交换完就退出，之后所有数据在 A、B 之间直连
- 关掉 `启动.bat`，房间码模式就不能用了（手动暗号/扫码仍然可用）

**它是可选的**，不是必需的。

## 手机上怎么装

```
互联网精神与世长存-0.4.2.apk     约 113 KB
```

**传到手机：**

1. **USB**：复制到手机，文件管理器点开安装
2. **局域网**：电脑跑 `启动.bat`，手机浏览器打开它显示的 `http://192.168.x.x:8642/`，点里面的 apk

安装时允许「未知来源应用」即可。

### 装完之后，房间码怎么用

APK 里的网页是手机本地的，它不知道你电脑的地址。所以要在 **设置 → 会合点地址** 里填一次：

```
http://192.168.x.x:8642
```

（就是 `启动.bat` 显示的那个「手机打开」地址）

**不填也能用**：手动暗号、扫码、局域网直连都不需要会合点。

> 以后可以把这一步做成自动发现，现在先手动填一次。

## 摄像头为什么起不来

这是浏览器的硬规定，不是 bug：

| 场景 | 摄像头 |
|---|---|
| 电脑 `http://127.0.0.1:8642` | ✅ |
| **手机浏览器** `http://192.168.x.x:8642` | ❌ 不是安全上下文 |
| **安卓 App**（内部用 127.0.0.1） | ✅ 但要给系统相机权限 |
| https 域名 | ✅ |

所以：
- **手机浏览器里扫码永远不行**，去用房间码或复制粘贴
- **App 里可以**，但第一次要允许相机权限；拒绝了就去
  `设置 → 应用 → 互联网精神与世长存 → 权限 → 相机`

现在点「扫码」会先检查系统权限，没给就直接告诉你怎么办，不会再干等着。

## 红白机联机（真正的双人）

游戏模式 → 游戏目录底部 **联机**：

1. 房主先打开一个 `.nes` 游戏（内置魂斗罗也行），点「创建」，得到一个 4 位房间码。
2. 对方点「加入」，输入房间码。
3. ROM 会**自动从房主发过去**（256 KB 约 1 秒），两边同时从第一帧开机。

技术上是一套**锁步同步**：

| 做法 | 说明 |
|---|---|
| 逐帧交换按键 | 每帧发一次 `{帧号, 按键位}`，本地按键也延迟 N 帧生效 |
| 不跑到对方前面 | 对方的执行位置作为闸门，两边永远同一帧 |
| 画面哈希对表 | 每 60 帧比一次画面采样哈希，对不上立刻提示「不同步」 |
| 延迟可调 | 4 / 6 / 10 / 14 帧；网络差就调大，操作会滞后一点 |
| 断线 | 对方掉线立刻提示，不会假装还在跑 |

限制：只支持红白机（NES）；PSP 那条路不在这个通道里；网慢的时候两边会一起变慢（这是锁步的代价，不是卡了）。

## 小说阅读器 + 听书

会话页底部的 **小说**（和「漫画」分开）。

- 读 `.txt` / `.md` / `.log` / **`.epub`** / `.html` / `.fb2`：
  txt 自动识别 UTF-8 / GBK / Shift-JIS / UTF-16；
  EPUB 按 OPF spine 拆章，HTML/FB2 也能拆；按「第 X 章」这类标题**自动分章**
- Calibre 转出来的 EPUB 常用 `<br>` 换行、没有 `<p>`，甚至正文直接挂在 `<body>` 下：
  已能按行拆段；没有章节标题的长文会自动按字数切成「正文 · N」节
- **正文里的插图**会嵌在文字中间显示（EPUB 内的图片按相对路径解析，实测 12 张全部加载）
- 只有**几乎没文字**（<500 字）的纯图片书才自动转漫画阅读器；
  文字+插图的混合书保持在文字阅读器里
- **分页模式（默认）**：一屏一页，左右翻页（按钮 / ← → / 滚轮 / 手机滑动）；
  顶部「分页 / 长条」一键切换，记在偏好里
- **点哪听哪**：点任意一句（或段落）就从那里开始朗读
- 目录跳章、A－/A＋ 调字号、记住每本读到第几章第几屏
- **听书**：逐句朗读、当前句高亮、自动滚动、可暂停；读完一章自动接下一章

听书用的是**「文乃」那条声线**——和服务端 `edge-tts` 的 `zh-CN-XiaoyiNeural` 一致
（rate −4%、pitch +4Hz、volume −8%，和 `E:\终端界面\bridge.py` 里的配方相同）。
声音由服务器合成并缓存到 `tts-cache/`，同一句只合成一次。

> 需要 `pip install edge-tts`（本机已装）。服务端没有它、或没有网时，
> 会自动退化成浏览器自带语音，并在状态栏标明「系统语音」。

## 完全离线的文乃音（已装好）

本机已经部署好 **GPT-SoVITS v2**（CUDA，RTX 4060 约 4–5G 显存），听书会优先走本地模型。

**怎么用**

1. 一般**不用单独启动**：`启动.bat` 发现 9880 没在跑，会自动在后台拉起 `启动语音.bat`
   （第一次加载模型约 30 秒，期间听书会显示「本地语音加载中…」并自动重试）
2. 正常打开程序听书 —— 状态栏会显示「本地朗读」，声音不再走网络
3. 关闭那个黑窗口就停

**放在哪**

| 内容 | 路径 |
|---|---|
| 运行环境（Python 3.12 + torch cu121） | `tts-local\venv` |
| GPT-SoVITS 源码 | `tts-local\src\GPT-SoVITS-main` |
| 模型（约 1.1G） | `...\GPT_SoVITS\pretrained_models` |
| 参考音 | `tts-local\refs\wenai_ref4.wav`（7.6 秒，已做响度标准化） |
| 接口配置 | `tts-local.json` |
| 日志 | `tts-local\logs` |

**一个必须知道的发现**：`可用音频` 里那 5 个 MP3 是**日语**（旁白，置信度 0.98），
不是中文。参考音换了三段之后，选了转写最可靠的一段：

- 参考文本：`その日を境に、突如として人々は不可思議な力に目覚めます`
- 参考音做了 **loudnorm 到 -15 LUFS，但绝不裁首尾静音**：
  裁了会让文本和音频对不齐，句子开头会冒出一小段含糊音（就是「杂音」的来源）；
  不裁、只提响度，输出电平从约 -34dBFS 提到 -12dBFS，听着才正常
- 自检：让模型念这句话本身，回听转写几乎逐字一致
- **日语朗读效果很好**（新句子回听基本逐字正确）
- **中文是跨语种**：音色对，但整句时常念错，不稳定

**主界面**：顶部三个入口「站点 / 书 / 游戏」用的是 `素材/` 里的图标，
游戏入口已从底栏移到顶部；标题栏左侧与「开始」按钮都贴了开始图标。

**改名 / 转格式**：资源 → 本机文件，每个文本文件后面有「改名」「转格式」。
转格式支持 txt ⇄ epub，生成新文件并进书架；改名会同步更新书架条目。

**接收 QQ / 微信的文件**：APK 注册了「用其他应用打开」和「分享」入口。
在 QQ/微信里长按文件 → 其他应用打开 →「互联网精神与世长存」，
或分享 → 更多 → 本应用；文件会存进书架并直接打开。

**音库**：书库 →「音库」，列出声线与导入的语音包，每行可「试听 / 使用 / 删除」。
内置文乃两条（默认 / 离线标签），语音包列表来自电脑端注册的包（文乃、麻美A、麻美B…）。

**书库**：底部六个「书库一~六」分栏；长按书本弹出菜单可换书库、收藏、缓存整本、删除。
「漫画 / 文库」筛选类型，点「收藏」数字只看收藏；「切换背景底图」可上传照片当书库背景。
进度条是经典 Win95 分段样式。

**缓存整本**：书库 →「语音缓存」进入勾选模式 → 勾选多本 → 再点一次开始批量缓存。
连着电脑时逐句合成并存在手机上，状态行显示「缓存 书名 · 12/220 句」，每本书下面
的进度条就是缓存进度；再点一次可停止，已缓存的部分不会重复合成。
书库里的阅读位置只记页码（副标题显示「第 2 章 · 第 5 页」）。

**语音包**：设置 →「导入语音包…」选一段 5~10 秒的干净录音，
再输入这段录音的**逐字台词**（用于对齐），服务器会把它存成
`tts-local/packs/` 下的新声线，之后在下拉里以「语音包：名字」出现。
底层还是 GPT-SoVITS 的参考音频，所以音色质量取决于录音干净程度和台词准确度。

**手机上的朗读**：连上电脑语音服务时，每句话的音频会自动缓存到本机；
之后离线也会**优先播放缓存的文乃音频**（声线列表出现「文乃（缓存）」），
没缓存的句子才退回安卓系统 TTS。
想听文乃的声音但不在电脑旁，用工具栏「导出」把整章合成成 WAV，
存进本机文件（也会下载一份），用播放器离线听。

**安卓后台播放**：APK 里听书会注册系统媒体会话，最小化后下拉控制中心/锁屏
可以看到「朗读 · 书名」，能暂停、继续、停止；前台服务 + wake lock 保证锁屏后继续读。
（手机上没有本地语音服务时，会退回系统 TTS 声线；连上电脑的服务器节点才会用文乃的声音。）

**最小化到播放器**：听书时点工具栏的「—」，阅读器收到底部 Winamp 播放器里，
显示书名和「第 X / N 句」进度条；播放器里能暂停/继续、前后翻句、拖进度跳句，
点标题或封面回到阅读器。

**录音**：小说工具栏有「● 录音」，点一下开始、再点停止；录音会存进本机文件，
同时下载一份（`朗读录音-日期时间.webm`），可以用来给我听问题。

**兜底语音也会按语言选声线**：本地和在线都失败时，日文用系统日语语音（ja-JP），
不再拿中文声线去念日文（那会只念汉字、跳过假名），并且状态栏会写明「系统日语语音」。

所以现在**按语言分流**（`tts-local.json` 的 `local_langs`）：

| 语言 | 用谁 |
|---|---|
| 日语 | 本地模型（文乃原声，同语种最准） |
| 中文 | edge-tts 晓伊（你终端里那条中文声线，稳定自然） |

把 `"local_langs": ["ja"]` 删掉，中文也会走本地（音色更像，但会念错字）。

阅读器会**自动判断语言**：句子里有假名就按日语合成，否则按中文；
日语文件里的「第一話 / 第二章」也能正确分章，Shift-JIS 编码的 txt 也能识别。

**语速**：底部的「慢 / 快」按钮，每按一次 ±10%，范围 −50% ~ +100%。
切换时会作废正在合成的旧请求（朗读代次 +1），不会出现两个声音叠在一起。
本地合成走 GPT-SoVITS 的 `speed_factor`（1.0 = 原速），在线语音走 edge-tts 的 rate；
两条路都会真正改变音频时长（实测 −20% → 5.94s，原速 → 4.96s，+20% → 4.0s）。
改完会**立即重念当前这句**，不用等下一句。

**声线**：下拉里三档——`自动`（日语本地 / 中文在线）、`本地模型`（强制离线）、具体在线声线。
切换后同样立即用新声线重念当前句，并弹出提示。

**服务接口**：`POST http://127.0.0.1:9880/tts`（GPT-SoVITS api_v2），
`serve.py` 的 `/__tts` 会先调它，失败才回落 edge-tts，再不行用浏览器语音。

## 原理

```
房间码模式                          手动暗号模式

 A ──(offer)──→ 会合点 ←──(取)── B      A ──暗号──→ B
 A ←──(answer)── 会合点 ←──(放)── B      A ←─应答码── B
        ↓ 之后直连                        ↓ 之后直连
 A ═══════════════════════════ B      A ═══════════════ B
```

- **暗号 = 压缩后的 SDP**（含 ICE 候选 + DTLS 指纹），约 660–780 字符
- **传输**：WebRTC DataChannel，64 KB 分块，每帧带 4 字节流 id
- **安卓壳**：WebView + 应用内 127.0.0.1 静态服务（保证安全上下文）
- **保存文件**：JS 分块 → Java → MediaStore 写进「下载/互联网精神与世长存/」

## 连不上怎么办

打开 **帮助 → 诊断日志…**，里面记录了每一步：

```
14:32:01  新建连接（STUN 开启）
14:32:01  收集状态 gathering
14:32:01  候选 host / udp / 192.168.1.7:54321
14:32:02  候选 srflx / udp / 203.0.113.9:61002
14:32:03  候选收集完成
14:32:06  ② 收到应答码
14:32:07  连接状态 connecting
14:32:09  ③ 数据通道已打开
14:32:09  ④ 收到对端资料：阿岚
```

**看两件事：**

1. **有没有 `srflx` 候选**
   - 只有 `host` → STUN 没通（可能被墙/被防火墙拦）。同一个 Wi-Fi 内仍然可以连；跨网络就不行。

2. **卡在哪一行**
   - 卡在「候选收集完成」→ 对方没收到你的暗号，或没回
   - 卡在「连接状态 connecting」→ 双方网络打不通（NAT/防火墙）
   - 出现 `失败` → 打洞失败，换网络或同一 Wi-Fi

点「复制全部」，把日志发给我就能定位。

## 手机和电脑不在同一个网络？

这是最难的情况，先把话说清楚：

| 场景 | 能不能连 | 靠什么 |
|---|---|---|
| 同一 Wi-Fi | ✅ 稳 | 局域网候选，不过公网 |
| 不同网络，双方都是普通家宽 | 🟡 看运气 | STUN 打洞 |
| 一方是手机流量（运营商 NAT） | 🔴 大概率不行 | 需要 TURN 中继（有带宽成本） |

**手机和电脑之间，房间码一定不work**——房间码靠电脑做会合点，电脑在自家局域网里，手机走流量根本够不到。

### 最省事的办法：让它们同一个网络

1. 手机开热点
2. 电脑连这个热点
3. 电脑双击 `启动.bat`
4. 手机浏览器打开它显示的那个 `http://192.168.x.x:8642/`
5. 房间码 4 位数字，秒连

这样完全不经过互联网，又快又稳。

### 非要跨网络

- **手动暗号**：能连，但要拿微信/邮件在两边搬 600 个字符，而且之后还得 NAT 配合
- **TURN 中继**：稳，但需要一台有公网带宽的服务器（设置里已支持填 `turn:主机:端口|用户名|密码`）

## 用公网 IPv6 跨网络（推荐先试这个）

如果电脑拿到的是公网 IPv6（`2404:` 开头那种），`启动.bat` 会多打印一行：

```
公网 IPv6:  http://[2404:c800:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx]:8642/
```

**手机只要也有 IPv6（国内移动网络基本都有），就能直接打开这个地址。**

打开之后：

- App 是电脑发过来的 → **房间码模式立刻可用**
- 电脑点「创建房间码」，手机输 4 位数字 → 直接连
- **全程没有应答码**

打不开的话，多半是路由器的 IPv6 防火墙拦了入站，去路由器里把 IPv6 防火墙关掉或放行本机。

查询本机 IPv6：`ipconfig` 里找 `IPv6 地址`（`2404:` / `240e:` / `2408:` 开头）。
## 安全

默认没有任何公网入口：中枢只在你本机/局域网跑，要开公网得手动点、并且会先弹确认。
威胁模型、安全部署方式、漏洞披露流程见 [SECURITY.md](SECURITY.md)。
